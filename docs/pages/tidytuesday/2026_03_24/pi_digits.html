Pi digits

Recherche de patterns dans un million de décimales de Pi
Author

Félix Marchais

Published

April 12, 2026

Cette semaine, le jeu de données porte sur le premier million de décimales de Pi. Cela me semble une bonne occasion de parler d’aléatoire. Pi étant infini, on s’attendrait à ce que les décimales apparaissent de manière aléatoire et donc que la répartition de chaque décimale de 0 à 9 devienne très stable (10% chacune) rapidement.

Nous allons vérifier cette hypothèse en deux temps

Prévalence des décimales

Dans un premier temps, nous allons créer un graphe en ligne montrant le taux d’apparition de chaque décimale.

Nous allons commencer par charger les packages et le jeu de données de cette semaine

library(tidytuesdayR)
library(dplyr)
library(tidyr)
library(ggplot2)

tuesdata <- tt_load("2026-03-24")

pi_digits <- tuesdata$pi_digits

Ensuite, on va créer une colonne pour chaque décimale, indiquant à chaque ligne (descendre d’une ligne = la décimale suivante de Pi) la somme cumulée d’apparition de cette décimale.

pi_digits_m <- pi_digits %>%
  mutate(
    `1` = cumsum(digit == 1) / digit_position,
    `2` = cumsum(digit == 2) / digit_position,
    `3` = cumsum(digit == 3) / digit_position,
    `4` = cumsum(digit == 4) / digit_position,
    `5` = cumsum(digit == 5) / digit_position,
    `6` = cumsum(digit == 6) / digit_position,
    `7` = cumsum(digit == 7) / digit_position,
    `8` = cumsum(digit == 8) / digit_position,
    `9` = cumsum(digit == 9) / digit_position,
    `0` = cumsum(digit == 0) / digit_position
  )

Maintenant, nous allons pivoter pour obtenir une ligne par position et par décimale (soit 10 lignes pour chaque décimale de Pi). Cette étape sera nécessaire pour créer notre graphe avec {ggplot2}.

pi_pivot <- pi_digits_m %>%
  group_by(digit_position) %>%
  pivot_longer(
    cols = `1`:`0`,
    names_to = "value",
    values_to = "cumsum"
  )
# pour alléger le graphe
# Après les 100 première décimales, on ne garde qu'une toutes les 1.000, jusqu'à 50.000
step <- 1000L
pi_pivot <- pi_pivot %>%
  filter(digit_position %in% c(1:100) | digit_position %% step == 0) %>%
  filter(digit_position < 50000)

On peut désormais créer notre graphe en ligne.

Chaque ligne représentera une décimale de 0 à 9. L’axe X représentera la position de la décimale dans Pi et l’axe Y son taux d’apparition

ggplot(
  pi_pivot,
  aes(x = digit_position, y = cumsum, group = value, color = value)
) +
  geom_line() +
  #geom_hline(yintercept = 0.1) +
  coord_cartesian(ylim = c(0.05, 0.15)) +
  labs(
    title = "Décimales de π : fréquence cumulative des chiffres (0–9)",
    subtitle = paste0(
      "1 point tous les ",
      as.character(step),
      " chiffres après 100; référence : 10 %"
    ),
    x = "Position dans les décimales",
    y = "Fréquence cumulative",
    color = "Chiffre"
  ) +
  theme_minimal(base_size = 12) +
  theme(legend.position = "right")

On observe en effet que les taux d’apparition s’équilibrent très vite autour de 0.1, avec une très faible dispersion, jusqu’à 0.105 dans les 10.000 premières valeurs, puis elles deviennent vite indiscernables.

A noter que cette dispersion apparaît sur le graphe car j’ai choisi de limiter l’axe Y entre 0.05 et 0.15. Si l’on avait mis l’axe Y de 0 à 1 ou de 0.90 à 0.110, la dispersion visible aurait été différente.

4-Gram Matrice

Une matrice 4-Gram est une matrice montrant la distribution de valeurs comprises entre 0000 et 1000 (les nombres composés de 4 chiffres) en affichant les deux premiers numéros sur l’axe Y et les deux derniers sur l’axe X.

J’ai vu cette visualisation pour la première fois dans un article l’utilisant pour montrer les patterns dans des codes PINs ayant fuité. Vous pouvez retrouver ce graphe sur informationisbeautiful.net

Nous allons faire la même chose ici pour voir si l’on peut observer des patterns, en faisant glisser les séquences de 4 chiffres le long du million de décimales contenues dans le jeu de données.

library(dplyr)
library(tidyr)
library(ggplot2)
library(scales)

# convertir digit en character, pour pouvoir concaténer ensuite
pi_sorted <- pi_digits %>%
  mutate(
    digit = as.character(digit)
  )

# Construire les 4 chiffres successifs via lead()
quad_counts <- pi_sorted %>%
  mutate(
    # d1 : digit courant
    d1 = digit,
    # d2, d3, d4 : digits suivants (fenêtre glissante)
    # lead(digit, k) = digit à la position i+k
    d2 = lead(digit, 1),
    d3 = lead(digit, 2),
    d4 = lead(digit, 3)
  ) %>%
  # On supprime les dernières lignes qui n’ont pas 4 digits complets
  # (les 3 dernières lignes auront d4 = NA)
  filter(!is.na(d4)) %>% # garde les fenêtres complètes
  mutate(
    # prefix : concaténation des 2 premiers digits (d1d2)
    prefix = paste0(d1, d2),
    # suffix : concaténation des 2 derniers digits (d3d4)
    suffix = paste0(d3, d4)
  ) %>%
  # Comptage : pour chaque couple (prefix, suffix), on compte le nombre d’occurrences
  # => donne une table de fréquences (jusqu’à 100×100 = 10 000 combinaisons)
  count(prefix, suffix, name = "n")

# Interprétation :
# Chaque occurrence correspond à un 4-gram "chevauchant" :
# position i..i+3, puis i+1..i+4, etc.
# C’est le choix standard pour détecter des motifs locaux (comme pour les PINs).

# 3) Préparer la grille complète 00..99 pour X et Y
all2 <- sprintf("%02d", 0:99)
# all2 = c("00","01",...,"99")
# Sert à forcer l’affichage de toutes les combinaisons même si absentes (n=0).

# 4) Compléter la matrice : rendre explicites les combinaisons manquantes
quad_full <- quad_counts %>%
  # complete() remplit toutes les combinaisons prefix × suffix
  # et met n = 0 quand la combinaison n’existait pas dans les données
  complete(prefix = all2, suffix = all2, fill = list(n = 0)) %>%
  mutate(
    # Facteurs avec niveaux ordonnés "00"->"99" pour un axe ordonné et stable
    prefix = factor(prefix, levels = all2),
    suffix = factor(suffix, levels = all2)
  )

# À ce stade :
# quad_full a toujours 10 000 lignes (100×100),
# ce qui est parfait pour une heatmap stable et comparable.

# Écart par rapport à l’attendu uniforme

# Nombre total de fenêtres de longueur 4 possibles :
# si on a N digits, il y a (N - 3) fenêtres chevauchantes de taille 4
total_windows <- nrow(pi_sorted) - 3L

# Attendu sous hypothèse d’uniformité "parfaitement" répartie :
# 10 000 séquences possibles (0000..9999) => ici compressées en (prefix,suffix)
# chaque cellule attendue = total_windows / 10000
expected <- total_windows / 10000

quad_dev <- quad_full %>%
  mutate(
    # diff : écart absolu à l’attendu (en nombre d’occurrences)
    diff = n - expected,

    # rel : écart relatif (proportionnel), pratique pour comparer
    # rel = (observé - attendu) / attendu
    rel = (n - expected) / expected
  )

# Interprétation :
# rel = 0     => exactement comme attendu
# rel = 0.10  => +10% plus fréquent que prévu
# rel = -0.10 => -10% moins fréquent que prévu
# Sur 1e6 digits, l’attendu est ≈ 100 occurrences par cellule (ordre de grandeur),
# donc les fluctuations naturelles seront visibles mais modestes.

#  Heatmap des écarts relatifs
ggplot(quad_dev, aes(suffix, prefix, fill = rel)) +
  # geom_tile : un carré par combinaison (prefix,suffix)
  geom_tile() +
  # Échelle divergente : bleu = moins fréquent, rouge = plus fréquent
  # midpoint=0 centre la palette sur "aucun écart"
  scale_fill_gradient2(
    low = "#2c7bb6",
    mid = "white",
    high = "#d7191c",
    midpoint = 0,
    labels = percent_format(accuracy = 0.1)
  ) +
  scale_x_discrete(
    breaks = seq(0, 100, by = 5) # Tick marks every 10 units
  ) +
  scale_y_discrete(
    breaks = seq(0, 100, by = 5) # Tick marks every 10 units
  ) +
  labs(
    title = "π — Écart relatif à l'uniforme (séquences de 4 chiffres)",
    subtitle = "Bleu = moins fréquent que prévu, rouge = plus fréquent que prévu",
    x = "Suffixe (d3d4)",
    y = "Préfixe (d1d2)",
    fill = "Écart relatif"
  ) +
  # carrés proportionnés (sinon la heatmap serait étirée)
  coord_equal() +
  theme_minimal(base_size = 12) +
  theme(
    # Axes denses (100 niveaux) : on réduit la taille et on pivote X
    axis.text.x = element_text(size = 6, angle = 90, vjust = 0.5, hjust = 1),
    axis.text.y = element_text(size = 6)
  )

Même si l’on observe pas de patterns comme dans la répartition des codes PINs, on remarque que la distribution n’est pas homogène : certaines combinaisons atteignent les +40% et -20% d’apparitions.

Ce graphe nous rappelle deux choses : Premièrement, Pi n’est pas un nombre “aléatoire”, mais une observation d’un rapport entre le rayon d’un cercle et son diamètre. Deuxièmement, répartition aléatoire ne veut pas dire “homogène”, et c’est un point crucial !

De nombreux logiciels utilisant des fonctions “aléatoires” trichent en réalité. Ce sont des exemples que l’on a vu avec les playlists YouTube ou Spotify : lorsque celles-ci étaient purement aléatoires, les utilisateurs se plaignaient régulièrement que certains morceaux revenaient trop souvent, et d’autres pas assez. C’en est devenu une leçon de design et d’UX (experience utilisateur) : Pour que l’utilisateur ait une sensation d’aléatoire, il faut en réalité lui fournir un résultat homogène. C’est ce qu’on appelle l’illusion de randomisation ou designed randomness.
